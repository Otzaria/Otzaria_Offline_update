# error_reports_manager

**דיווחי טעויות שאוצריא לא הצליחה לשלוח** — נשיאתם מהמחשב הלא-מקוון אל
השרת של אוצריא, על אותו כונן שנושא את העדכונים. חבילת Dart טהורה (ללא
Flutter), במקביל ל-`custom_apps_manager`.

אוצריא עצמה לא שונתה: הלאנצ'ר קורא וכותב את התור שלה **ישירות**, ב-`user_state.db`,
ובונה את גוף הבקשה בעצמו — פורט של הקוד של אוצריא.

## הזרימה

1. **במחשב הלא-מקוון, בעלייה.** כשאוצריא מותקנת וסגורה, הלאנצ'ר סופר בתור שלה
   את הדיווחים שאפשר לשלוח. אם יש, הוא שואל אם לאסוף אותם; אם כן — כל דיווח
   נכתב לתיבת היציאה על הכונן, ואז מסומן באוצריא כנשלח.
2. **במחשב המקוון.** בכרטיס ההורדות מופיע "העלאת N דיווחים לאוצריא". כל
   דיווח נשלח ב-POST, 8 בדקה.

אין מסך, אין פריט ניווט ואין הגדרה — רק הדיאלוג והכפתור.

## איפה התור

`user_state.db` נמצא כמו ש-`AppPaths.resolveNotesDbPath` של אוצריא מוצא אותו
(`locateUserStateDb`):

1. `key-databases-path` מההגדרות של אוצריא, אם הוגדר;
2. אחרת `<dataRoot>/databases`, אם התיקייה קיימת;
3. אחרת `databases` שליד תיקיית הספרייה (`dirname(key-library-path)`).

התיקייה המועדפת נבחרת **רק אם אפשר לכתוב בה**, כמו `_writableDatabasesDirectory`
של אוצריא; אחרת `<dataRoot>/databases`. הבדיקה אינה יוצרת את התיקייה: תיקייה
חסרה נבדקת באב הקיים הקרוב, וקובץ הבדיקה נמחק. מועדפת כתיבה בלי מסד פירושה
שאוצריא הייתה פותחת שם מסד חדש — ולכן אין מה להציע, גם אם יש מסד ישן בנפילה.
`dataRoot` וההגדרות מגיעים מהאיתור שכבר קיים ב-`library_manager`
(`LibraryDbLocator.otzariaSettingsRoot`, כולל התקנה ניידת, ו-`OtzariaSettingsReader`
שקורא מעותק). **לעולם לא נוצר מסד או תיקייה**: אין מסד — אין מה להציע.

`<dataRoot>/error_reports_queue.hive` שעוד קיים פירושו שהתור לא הועבר מ-Hive —
ואז לא נוגעים בכלום.

## מה נקרא, ומה נכתב

| | |
| --- | --- |
| קריאה | `pending_reports` בסוג `error_reports_queue/pending_reports`, עם `busy_timeout=5000` |
| איפה זה רץ | כל עבודת ה-SQLite — פתיחה, בדיקת הסכמה, פענוח, ה-digest והסימון — ב-`Isolate.run` (מוזרק: `runIsolated`); רק כתיבת הקבצים לתיבה נשארת ב-isolate הראשי, אסינכרונית. FFI סינכרוני ב-isolate של הממשק מקפיא אותו בעלייה (AGENTS §5.9) |
| שמירת סכמה | `PRAGMA user_version` גבוה מ-`knownSchemaVersion` (1), או בלי הטבלה — לא נוגעים, אין הצעה |
| דיווח שלא יישלח | `schemaVersion` חדש מ-2, `fromJson` שנכשל, surrogate בודד (אין digest), גוף מעל 256KB — נשאר בתור |
| הסימון | `markPendingReportAsSent` של אוצריא, **בטרנזקציה אחת** (`BEGIN IMMEDIATE`): השורה לא השתנתה מאז הקריאה, רשומה באותו מזהה בהיסטוריה מוחלפת, הוספה, חיתוך ל-100, המונה, ומחיקה מהתור |
| המונה | `lists` (`error_reports_queue` / `sent_reports_total`) — גם הוא ב-`user_state.db`, ולכן מתעדכן באותה טרנזקציה, כמו `SentReportsCounter.increment(floor:)` |

⚠️ **הקובץ נכתב לתיבה לפני הסימון.** קריסה ביניהם משאירה דיווח שעדיין ממתין
באוצריא, ובאיסוף הבא הוא נכתב שוב באותו שם; בסדר ההפוך הוא היה מסומן כנשלח
בלי שום עותק. שורה שהשתנתה מאז הקריאה, או שהסימון שלה נכשל, אינה מועברת והקובץ
שלה נמחק — התיבה תמיד משקפת את אוצריא. הודעת החריג הולכת ליומן בלבד.

⚠️ **דיווח אחד לכל מזהה.** הסימון מוחק את *כל* השורות הממתינות באותו מזהה, ולכן
שורה שנייה באותו מזהה מצאה את עצמה נמחקת ומחקה את הקובץ שהראשונה כתבה. הראשונה
נבחרת, ומזהה שכבר הועבר בריצה לעולם אינו נמחק מהתיבה. השאילתות על `payload_json`
הן ב-SQL (`json_extract` בתוך `CASE WHEN json_valid`), בלי לפענח את התור כולו
בכל שורה.

**הרשומה בהיסטוריה היא הטקסט המקורי**, בלי סריאליזציה מחדש: אוצריא שומרת
`report.toJson()` של הדיווח המפוענח, ו-`fromJson` שלה קורא את שניהם זהה.

## הפורט של `toApiPayload`

`lib/src/port/` הוא פורט של `lib/models/direct_error_report.dart` ו-
`lib/utils/canonical_json.dart` באוצריא — רק מה שבונה את הגוף: `fromJson`
(כולל הצלת הצעת תיקון פגומה), `toApiPayload`, `apiErrorDetails` (בלוק ה-fallback
בנוסח של אוצריא, מילה במילה), `contentDigest` (OCJ-1 + SHA-256).

⚠️ **שינוי באוצריא בקבצים האלה מחייב שינוי כאן.** הבדיקות (`port_test.dart`)
משוות לוקטורים שהופקו מהקוד של אוצריא עצמה — ראו המקור בראש הקובץ ובשדה
`source` של `test/fixtures/api_payload_golden.json`. גרסת סכמה חדשה (3) פירושה
שהפורט אינו מכיר את הדיווח, והוא נשאר בתור.

## תיבת היציאה

`<stateDir>/reports/outbox` — **לא** תחת `mirror/`. ניקוי המראה
(`MirrorJunkSweeper`) וביטול הורדה (`MirrorDownloadUndo`) מוחקים מה שאף מניפסט
אינו מכיר, ודיווח שעוד לא נשלח לא יהיה במניפסט לעולם. בכונן לקריאה בלבד
התכונה כבויה כולה. קובץ נכתב לקובץ זמני ואז `rename`, בשם שנגזר מ-`report_id`
בתווים בטוחים בלבד.

## ההעלאה

- **רק כתובת https לשרת `otzaria.org`.** קובץ על כונן יכול להגיע מכל מקום;
  כתובת אחרת אינה נשלחת, והקובץ נמחק כנדחה.
- **מנות של 8, והמתנה של 65 שניות ביניהן — מסוף הבקשה האחרונה במנה.** השרת
  מקבל 8 דיווחים לדקה מכל כתובת, ומדידה מתחילת המנה הייתה מקצרת את ההמתנה
  בכל פעם שבקשה אחת התעכבה. החלון נשמר ב-`ErrorReportUploader` לכל אורך ההרצה,
  כך שהמשך מיד אחרי עצירה עדיין ממתין. מעל מנה אחת הלאנצ'ר מסביר קודם כמה זמן
  זה ייקח.
- **429 אינו עוצר.** ממתינים חלון שלם ושולחים שוב את אותו דיווח — עד
  `maxRateLimitRetries` פעמים (3), ורק אז הריצה נעצרת.
- כתובת אסורה נבדקת **לפני** ההמתנה: היא אינה בקשה לשרת ואינה נספרת בחלון.
- **עצירה מיידית**, גם באמצע ההמתנה וגם באמצע בקשה. בקשה שננטשה משאירה את
  הקובץ; שליחה חוזרת נענית `duplicate:true` ונחשבת הצלחה.
- **ההמשך הוא פשוט מה שנשאר בתיבה.** אין קובץ מצב.

| תשובה | מה קורה לקובץ |
| --- | --- |
| 2xx (כולל `duplicate:true`) | נמחק — נשלח |
| 400 / 409 / 413 / 422 | נמחק — נדחה סופית; הסיבה נרשמת ביומן |
| 429 | נשאר; המתנה של חלון ואותו דיווח שוב (עד 3 פעמים) |
| כל השאר, זמן קצוב, שגיאת רשת | נשאר; הריצה נעצרת עם הודעת שגיאה |

2xx ולא רק 200 — **הבדל מכוון מאוצריא**, שמקבלת רק 200 (`_trySend`) ומשאירה כל
קוד אחר בתור לניסיון חוזר. כאן 201 שהיה נחשב "שגיאה זמנית" היה נשאר בתיבה, עוצר
כל ריצה ונשלח שוב לנצח.

## מבנה

```
lib/src/
├── models/
│   ├── outbox_report.dart     — קובץ בתיבה + בדיקת הכתובת המותרת
│   └── upload_result.dart     — התקדמות, סיכום, עצירה
├── port/                      — פורט מאוצריא; ⚠️ לשמור בהתאמה
│   ├── canonical_json.dart
│   └── direct_error_report.dart
└── services/
    ├── user_state_report_queue.dart — איתור `user_state.db`, קריאה והעברה
    ├── report_outbox.dart           — התיבה על הדיסק (ממשק + מימוש)
    └── report_uploader.dart         — השליחה (http.Client, המתנה ושעון מוזרקים)
```

## מה אומת בפועל

בדיקות יחידה בלבד: מול מסד שנבנה בסכמה של אוצריא, `MockClient`, ווקטורים
מהקוד של אוצריא. **לא** הורץ מול `user_state.db` אמיתי של התקנה, ולא מול השרת
האמיתי.
